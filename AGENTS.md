# tiny-fps

Tiny multiplayer first-person game for the browser: a rooftop capture-the-flag with parkour movement, in progress (see [docs/PLAN.md](docs/PLAN.md)). A personal project on `korial29`: never move or mirror it to an organisation. Tooling, CI and the transport layer come from `korial29/air-hockey` (`~/dev/air-hockey`): when in doubt, do what air-hockey does.

Read this file before any change. Change a gameplay rule only when the user asks.

## Commands

Node 24 (`.nvmrc`).

```bash
npm start           # demo with hot reload (Vite)
npm run dev:server  # WebSocket server on :8787
npm test            # Vitest
npm run lint        # Prettier + ESLint + tsc --noEmit
npm run build       # dist/: client, local, server, types
npm run size        # gzip budgets
```

## Size comes first

- Budgets, gated by `npm run size`: `dist/index.js` ≤ 40 KB gzip, `dist/local.js` ≤ 16 KB (raised by the user: from 12 and 6 for parity with the js13k game, then from 30 and 12 for level design). Raise one only when the user agrees. After step 1 of the plan they stand at 15.1 and 4.3 KB.
- No game or 3D library, no runtime dependency, no images, fonts or assets: geometry and textures are generated in code.
- Raw WebGL2: one scene program (depth passes included) and one small post-processing program. No three.js, no WASM.
- Do not copy code from `carlini/js13k2019-yet-another-doom-clone`: it is GPL-3.0, this project is Apache-2.0. Its ideas (procedural textures, maps as compact data, shadow maps, jsfxr-style sound) are fair game; reimplement them.

## Architecture

- **The host is authoritative**: the Node server or the local host tab.
- **Inputs, not positions**: the client sends one `Input` per step (11 bytes, 60 Hz): held keys (8 bits: forward, back, left, right, jump, sprint, dash, crouch), yaw, pitch, a u16 `seq`, and the `view` tick it draws the others at. The host applies each input on arrival with `move()` and acks the last seq per player in the snapshot. A bank of `INPUT_BURST` inputs per player stops speed hacks.
- **The client predicts** its own player: it applies its inputs at once, and on each snapshot resets to the host state and replays the unacked inputs. Other players are drawn `INTERP_DELAY` (100 ms) in the past, interpolated between snapshots.
- **Snapshots** at 30 Hz (`SNAP_EVERY` 2 of `TICK_HZ` 60): a 4-byte head (type, tick, player count), 39 bytes per player (position, velocity, the grabbed ledge, look angles, the last acked seq, the movement mode, the time in it, the wall side, the jumps and dash left and their timers: all a `move()` needs to continue from), then the match: 4 bytes (captures of red and blue, the clock in whole seconds with an over bit) and one state byte per flag, with the carrier's id when carried and the resting place and the seconds left when dropped. Both flags home is 6 bytes over the players. The end of a match is a text message (`end`: the score and each player's name, team, captures and returns).
- **One map, no progression**: the room plays `ROOFTOPS` (`map.ts`), or the `WorldDef` given to its constructor. There is no level index, no health, no pickup and no weapon.
- **Teams**: red (0) and blue (1) from `TEAM`. A joiner goes to the smaller team, red on a tie; nobody is moved when someone leaves, the next joiner fills the smaller side. `PlayerInfo.team` and `color` (the team's colour, so the runner code needs nothing) are in the roster. A team spawns at its own `WorldDef.teams[team].spawns`, and so does a fall: `move()` takes the team as its last argument and the client's predictor gets it from `you(id, team)`. A fall puts `EV.RESPAWN` in `ev`, which the host reads.
- **Capture the flag** (`ctf.ts`, ticked by the room at `TICK_HZ`): a flag is home (on its team's base), carried (by a player id) or dropped (a point and a timer). A player touches a flag within `FLAG_REACH` (1.5 m) sideways, with his body overlapping its `FLAG_H` height. An enemy takes a flag at home or lying; a teammate sends a lying one home at once (a returner is counted), before an enemy can take it; a lying flag goes home after `FLAG_RETURN` (10 s). A carrier at his own base while his own flag is home scores one and the carried flag goes home. A carrier who falls under the kill floor drops it where he last stood on a floor, and so does one who leaves. `Room.drop(id)` is the hook of the tackle (step 7): the flag falls under the carrier (on the floor below him in the air, at his last ground over the void), and he cannot take it back for `FLAG_LOCK` (2 s). The flags never change a `PlayerState`, so prediction is the same with or without them.
- **A match** runs to `rules.scoreLimit` (3) captures or `rules.timeLimit` (480 s), the most captures winning and a level score a draw. Then the end screen runs `END_SCREEN` (10 s), the scores and flags reset and everyone is put back at a spawn of his team. An empty room starts from scratch. The client reads takes, drops, returns, captures and new matches off two snapshots in a row (`beats.ts`) for the banners and the sounds.
- **Movement** (`physics.ts`, constants in `constants.ts`): `move()` is one step of a state machine over `MODE` (ground, air, wall-run, hang, climb, slide, crouch). Ground control accelerates toward the wished direction, kills the speed across it (`GRIP`) and has friction; the sprint is slow acceleration past `RUN_SPEED`. A dash is a burst (`DASH_TICKS`, no gravity), once on the ground or once in the air per landing, with a cooldown. Jump, dash and the rest are presses (edges on `held`, not holds); a press is kept `JUMP_BUFFER_TICKS` and a jump works `COYOTE_TICKS` after an edge. A ledge is caught in the air on a side the player faces, a top `GRAB_MIN` to `GRAB_MAX` above the feet with room above it; a wall-run starts in the air with forward held, from `WALLRUN_MIN_SPEED` (a normal run is enough) toward or along a wall within `WALL_REACH`, at most `WALL_PARALLEL` of the speed into it: the velocity is turned along the wall (`WALL_TURN_KEEP` of the speed), lifted, and the body is drawn in to the wall (`WALL_PULL`). The state is float32 and `Math.hypot` is not used, so host and client agree to the bit. The animation reads `PlayerState.ev` (`EV` bits of the last step) and `fall`, not sent; the predictor's `events()` hands the live ones out once. Keys: WASD, Shift, Space, C; a dash is a move key pressed twice within `DOUBLE_TAP_MS` (250 ms, `input.ts`): the step after the second press carries the DASH bit and only the tapped direction (`Controls.take()`), so the burst goes that way whatever else is held, with no wire change.
- **Brush world** (`world.ts`, `physics.ts`): solid axis-aligned boxes, floors are tops, walls are sides, boxes may float. `build()` lists each brush in the 4 m grid cells its footprint covers; physics asks `near()` for the few candidates, `ray()` walks the cells the ray crosses with an exact slab test. The player is a cylinder: it slides along box sides, steps onto a top at most `STEP_H` above the feet, stands on the highest top under its circle, bumps its head on bottoms, and goes back to the spawn of its id in its team under `def.floor`. Sides are judged from the feet at the start of the step. A spawn is `[x, y, z, yaw]`.
- **Lag compensation history** (`room.ts`): every snapshot tick the room keeps the players' states for `MAX_REWIND` ticks. `rewind(id, view)` answers the other players as player `id` drew them at the `view` tick of one of its inputs, interpolated the way the client does. Nothing calls it yet: the tackle of step 7 will, with `Room.drop()`. `ray()` and `hidden()` (`world.ts`) are the generic ray and line of sight through the brushes, for the same use.
- **Lighting** (`render.ts`): the sector light is a dim ambient; up to `MAX_LIGHTS` spots and points from `gather()` (`lights.ts`: the flashlights, the lava) add up in the one shader program, and the first `MAX_SHADOWS` shadowed spots get a depth pass into a shadow-map array (the same program, colour writes off). Lava and the unlit layer -2 light themselves. The lit scene goes into a 4x multisampled offscreen target (RGBA16F with `EXT_color_buffer_float`, RGBA8 otherwise), resolved to a texture; the post program adds a three-level bloom, a tone shoulder, a vignette, grain and gamma.
- **`src/shared` never touches the DOM or Node APIs.**
- Coordinates: metres, y up, yaw 0 looks toward -z, `forward(yaw) = (-sin yaw, -cos yaw)` on x, z.
- Keys are read by `KeyboardEvent.code`: WASD on QWERTY is ZQSD on AZERTY with no extra code.
- `erasableSyntaxOnly` is on: no enums, no parameter properties, no namespaces.

## Tests

- Vitest. A fix comes with a test that fails without it.
- Prediction must be checked against the room: the same inputs through the room and through the predictor end at exactly the same place (state is float32 on both sides).
- Visual work: render the built client with a fake socket in headless Chromium, look at the screenshot, then report.

## Git, PRs and releases

- Same flow as air-hockey: branch from `master` (`feature/…`, `fix/…`), one release label per PR, rebase on `origin/master` with `--force-with-lease`, conventional commit subjects in English.
- The PR's label picks the bump (`release:major`, `release:minor`, `release:patch`); `release:skip` publishes nothing. A merge releases at once, with no approval (single maintainer): npm publish, `vX.Y.Z` tag, GitHub Release, built from the PR's merge commit, one release at a time.

## Working with several agents

- The shared contract (types, constants, signatures) is committed first.
- Each agent gets its own worktree from that commit and owns its files; merge by hand, run every check, then look at a screenshot.

## Writing

- English for code, comments, docs, commits and PRs.
- Comments state the non-obvious fact and stop.
